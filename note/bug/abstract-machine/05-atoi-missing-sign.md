## 〇、前置知识：`atoi` 是什么

### 名字

**`atoi` = ASCII to integer**，读作「A-to-I」。

- `ASCII`（American Standard Code for Information Interchange，美国信息交换标准代码）就是"字符如何用数字编号"的那张表：字符 `'0'` 编号 48（0x30），`'A'` 编号 65，空格编号 32。
- 中文一般叫**「字符串转整数」**，没有统一的官方译名。

同族函数的命名规律是 `a` + `to` + 目标类型：

| 函数      | 转成          | 中文                                    |
| ------- | ----------- | ------------------------------------- |
| `atoi`  | `int`       | 字符串转整数                                |
| `atol`  | `long`      | 字符串转长整数                               |
| `atoll` | `long long` | 字符串转长长整数                              |
| `atof`  | `double`    | 字符串转浮点数（`f` 是 float，但返回的其实是 `double`） |

### 它解决什么问题

字符 `'1'` 在内存里存的是 **0x31（十进制 49）**，不是 1。所以这样是错的：

```c
char c = '7';
int x = c;        // x 得到 55，不是 7
```

而命令行参数、配置文件、串口收到的输入**全都是字符**。要让它们参与运算，必须先做一次"文本 → 数值"的转换，这就是 `atoi` 的职责：

```c
atoi("123")   →  123     // 三个字符 '1''2''3' 变成一个整数 123
```

原理是逐位累加：`x = x * 10 + (当前字符 - '0')`。减 `'0'` 就是把 ASCII 编号（0x31）还原成数值（1）。

### 原型与出处

```c
#include <stdlib.h>              // 标准位置
int atoi(const char *nptr);      // 本项目在 klib.h 里声明
```

- 参数名 `nptr` = **n**umber **p**oin**t**e**r**，指向待转换的字符串。
- `const char *` 表示"指向不可修改的字符序列的指针"——`atoi` 只读不写。

### 标准行为（C99 §7.20.1.2）

标准把它定义得很简洁：**除了出错时的行为，`atoi(s)` 等价于 `strtol(s, NULL, 10)`**。展开来说，它按顺序做四件事：

1. **跳过前导空白**。"空白"由 `isspace()` 定义，共 6 个字符：空格 `' '`、制表符 `'\t'`、换行 `'\n'`、垂直制表 `'\v'`、换页 `'\f'`、回车 `'\r'`。
2. **接受一个可选的符号**：`'+'` 或 `'-'`，最多一个。
3. **读取连续的十进制数字**，遇到第一个非数字字符就停下（不报错，直接返回已读到的部分）。
4. **一个数字都没读到就返回 0**。

行为一览：

| 输入 | 标准返回 | 说明 |
| --- | --- | --- |
| `"123"` | `123` | 正常 |
| `"-5"` | `-5` | 负号 |
| `"+7"` | `7` | 正号也合法 |
| `"  42"` | `42` | 跳过前导空格 |
| `"\t42"` | `42` | 制表符也是空白 |
| `"12abc"` | `12` | 遇 `'a'` 停止，**不报错** |
| `"abc"` | `0` | 一个数字都没读到 |
| `"- 5"` | `0` | 符号与数字之间不许有空格 |
| `""` | `0` | 空串 |
| `"99999999999"` | **未定义** | 超出 `int` 范围，C 标准不保证任何行为 |

### ⚠️ 它没有错误通道

这是 `atoi` 最要命的设计缺陷：**返回 0 时你无法区分三种情况**——

- 输入真的是 `"0"`；
- 输入是 `"abc"`，解析失败；
- 输入是 `"-5"` 但实现有缺陷（正是本文要讲的）。

正因如此，现代 C 一律推荐用 **`strtol`** 代替：它通过 `endptr` 参数告诉你"解析停在哪个字符"，通过 `errno` 报告溢出。`atoi` 只适合"输入一定合法"的场合。

> 📌 记住这个区分：**`atoi` 是便利函数，`strtol` 是正确函数。** klib 目前只有前者。

## 一、题目

```c
int atoi(const char *nptr) {
  int x = 0;
  while (*nptr == ' ') { nptr++; }
  while (*nptr >= '0' && *nptr <= '9') {
    x = x * 10 + *nptr - '0';
    nptr++;
  }
  return x;
}
```

找出它与标准 `atoi` 的两处行为差异。

<details>
<summary>答案</summary>

1. **不识别 `'+'` / `'-'` 符号**：`atoi("-5")` 返回 `0` 而不是 `-5`；
2. **跳过的空白字符不全**：只跳空格，不跳 `\t` `\n` `\v` `\f` `\r`。`atoi("\t42")` 返回 `0`。

</details>

## 三、原理：为什么这个 bug 特别安静

### 3.1 失败形态是"返回 0"，而不是报错

```c
atoi("-5")   → 0        // 而不是 -5
atoi("abc")  → 0        // 标准也是 0，无法区分
atoi("0")    → 0        // 合法输入也是 0，更无法区分
```

调用方拿到 `0` 时**没有任何办法判断**这是"解析出的真值"、"解析失败"还是"符号没被认出来"。`atoi` 的接口设计本身就不提供错误通道——这是 C 标准库的历史遗留（正因如此，现代 C 推荐用 `strtol`，它通过 `endptr` 和 `errno` 报告失败）。

### 3.2 它在什么场合会咬人

`atoi` 在这个项目里的主要使用场景是**解析命令行参数和配置字符串**：

- `nanos-lite` / `navy-apps` 里从 `mainargs` 取参数；
- 未来实现 shell 或调试器命令时解析用户输入；
- 任何从字符串读配置的地方。

一旦有人传了负数（坐标偏移、温度、相对跳转量……），你会得到一个 `0`，然后程序带着这个 `0` 一路跑下去，在很远的地方表现为"逻辑不对"。

### 3.3 `'\t'` 那一半为什么也重要

命令行参数经过 shell、Makefile、`MAINARGS` 宏几层传递，混进制表符完全可能。而且 `atoi("\t42")` 返回 0 的失败形态和上面一模一样——安静。

## 四、修复

```c
// 将十进制字符串转换为 int，跳过前导空白，识别可选的 '+' / '-' 符号
int atoi(const char *nptr) {
  int x = 0;
  int neg = 0;

  // isspace() 的全集：空格与 \t \n \v \f \r（后者在 ASCII 中是连续的 0x09~0x0d）
  while (*nptr == ' ' || (*nptr >= '\t' && *nptr <= '\r')) { nptr++; }

  if (*nptr == '-' || *nptr == '+') {
    neg = (*nptr == '-');
    nptr++;
  }

  while (*nptr >= '0' && *nptr <= '9') {
    x = x * 10 + *nptr - '0';
    nptr++;
  }

  return neg ? -x : x;
}
```

几个细节：

- **`'\t' <= c && c <= '\r'` 这个技巧**：ASCII 里 `\t`(0x09) `\n`(0x0a) `\v`(0x0b) `\f`(0x0c) `\r`(0x0d) 恰好连续，一个区间判断顶五个比较。空格(0x20)不连续所以单列。这正是 libc 里 `isspace()` 的实现方式。
- **符号只允许出现一次，且必须紧跟在空白之后**——这是标准行为。`atoi("- 5")` 和 `atoi("--5")` 都返回 0，是对的。
- **累加仍在正数域进行，最后取反**。这样 `INT_MIN`（-2147483648）在中间步骤 `x` 会溢出。见下面的遗留。

最后一条是本次最想立的规矩：**简化实现是完全可以的，裸机上本来就不该背标准库的全部包袱。但简化必须写在注释里**，否则它就从"有意的取舍"退化成了"不知道的缺陷"。上游那份 `atoi` 的问题不在于简化，而在于**没写自己简化了什么**。

## 六、遗留（本次未处理）

1. **不检测溢出。** `atoi("99999999999")` 会静默回绕。标准 `atoi` 对溢出也是 UB，所以这不算偏离标准；真正需要检错的场合应该用 `strtol`——而 klib 目前没有 `strtol`。
2. **`INT_MIN` 无法正确解析。** `atoi("-2147483648")`：中间的 `x` 要先达到 `2147483648`，超出 `int` 范围。正确做法是在负数域累加（`x = x * 10 - (*nptr - '0')`）。没改是因为它会让主循环变复杂，而当前没有任何调用方需要 `INT_MIN`；**若将来 klib 加了 `strtol`，应当在那里一次做对，并让 `atoi` 变成它的薄包装**。
3. **没有 `atol` / `atoll` / `strtol` / `strtoul`。** 等有调用方需要再补。
