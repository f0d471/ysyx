📖 AXI4 单次传输参考（非burst，NPC当前只需这个）

读事务 (IFU取指 / LSU load)

arlen   = 8'h0    // 1拍
arsize  = 3'b010  // 4字节
arburst = 2'b01   // INCR
arid    = 4'h0    // 固定即可

时序：
T0: arvalid=1, araddr=目标地址
T1: arready=1 → 握手成功
T2: rvalid=1, rdata=数据, rresp=OKAY, rlast=1
     rready=1 → 握手成功

写事务 (LSU store)

awlen   = 8'h0    // 1拍
awsize  = 3'b010  // 4字节
awburst = 2'b01   // INCR
wlast   = 1'b1    // 只有1拍

时序：
T0: awvalid=1, awaddr=目标地址
T1: awready=1 → 写地址握手
T0: wvalid=1, wdata=数据, wstrb=掩码, wlast=1
T1: wready=1 → 写数据握手
T2: bvalid=1, bresp=OKAY
     bready=1 → 写回复握手

⚡ 关键差异总结

  • SimpleBus 双通道握手（req + resp）
  • AXI4 五通道分离（AR / R / AW / W / B）
  • arsize / awsize —— 指示实际传输宽度（解决 UART 寄存器问题）
  • arlen / awlen —— burst 长度（当前设0即可，单次传输）
  • arburst / awburst —— burst 类型（设 INCR=01）
  • rresp / bresp —— 响应码（OKAY=00, SLVERR=10, DECERR=11）
  • rlast / wlast —— burst 结束标志（单次传输时恒为1）
  • arid / rid / awid / bid / wid —— 事务 ID（固定0即可）
  • Arbiter —— 合并 IFU/LSU 到单 AXI4 端口
  • 顶层模块重命名为 ysyx_XXXXXXXX
  • reset 改为高电平有效
  • IFU 和 LSU 不会同时发请求（多周期），arbiter 策略可简单

💡 实现建议

  • 先做单次传输：arlen=0, awlen=0, 不实现 burst，够用到接入 SoC
  • 读写通道独立：AXI4 读写可并行，但你的多周期 NPC 不会同时读写
  • arbiter 可简化：IFU 和 LSU 不会同时发请求，固定优先级即可
  • 先通后优：先让 NPC 在 ysyxSoC 中跑起来，再优化时序
  • 复位PC不变：ysyxSoC 中 Flash 映射到 0x3000_0000，但 MROM 在 0x2000_0000
    接入 SoC 后再改复位地址
  • rresp 检查：收到非 OKAY 响应时触发 Access Fault，方便调试
