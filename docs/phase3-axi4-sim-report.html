Phase 3 技术报告

AXI4 仿真验证 · sim_top.sv 完全重写 · core + arbiter + AXI4 Slave 存储器模型

0概述

Phase 3 的目标是将仿真环境从"SimpleBus + DPI-C 直连"改造为"core → arbiter → AXI4 Slave"的完整链路，验证 AXI4 协议在仿真中能正确工作。

改动范围：仅 sim_top.sv 一个文件，从 186 行重写为 339 行。其他文件不变。

5AXI4 Slave 存储器模型（核心新增）

这是 Phase 3 的主要新增内容。它模拟一个真实的 AXI4 Slave 设备：接收读写请求，经过随机延迟后返回响应。

5.1 LFSR 随机数生成器

📄 sim_top.sv · 第 193-202 行
localparam MAX_DELAY = 4;

// LFSR
logic [7:0] lfsr;
always_ff @(posedge clk or negedge rst_n) begin
    if (!rst_n)
        lfsr <= 8'hA5;
    else
        lfsr <= {lfsr[6:0], lfsr[7] ^ lfsr[5] ^ lfsr[4] ^ lfsr[3]};
end

8-bit 线性反馈移位寄存器，每个时钟周期生成伪随机数。取低 2 位 lfsr[1:0] 作为延迟基数，经过 % MAX_DELAY + 1 得到 1~4 周期的随机延迟。共享给读写两个通道。

5.2 读通道状态机

📄 sim_top.sv · 第 204-270 行
// --- 读通道状态机 ---
typedef enum logic [1:0] {
    RD_IDLE  = 2'd0,   // 等待 AR 握手
    RD_DELAY = 2'd1,   // 模拟延迟
    RD_RESP  = 2'd2    // 输出 R 响应
} rd_state_t;

状态转移逻辑

📄 sim_top.sv · 第 224-241 行
always_comb begin
    rd_state_next = rd_state;
    case (rd_state)
        RD_IDLE: begin
            if (m_arvalid && m_arready)       // AR 握手成功
                rd_state_next = RD_DELAY;
        end
        RD_DELAY: begin
            if (rd_delay_cnt >= rd_delay_target) // 延迟到期
                rd_state_next = RD_RESP;
        end
        RD_RESP: begin
            if (m_rvalid && m_rready)         // R 握手成功
                rd_state_next = RD_IDLE;
        end
    endcase
end

AR 握手

📄 sim_top.sv · 第 243-244 行
// 读请求握手：始终就绪
assign m_arready = (rd_state == RD_IDLE);

Slave 在空闲时始终准备好接收读请求。这是最简单的实现——真实设备可能有请求队列满的情况。

延迟计数 + 数据获取

📄 sim_top.sv · 第 246-263 行
always_ff @(posedge clk or negedge rst_n) begin
    if (!rst_n) begin
        rd_delay_cnt    <= '0;
        rd_delay_target <= '0;
        rdata_buf       <= 32'h0;
        rresp_buf       <= `AXI4_RESP_OKAY;
    end else if (rd_state == RD_IDLE && m_arvalid && m_arready) begin
        // 握手成功，开始延迟
        rd_delay_target <= 4'(lfsr[1:0] % MAX_DELAY) + 4'd1;
        rd_delay_cnt    <= 4'd1;
        // 同时读取数据
        rdata_buf <= paddr_read(m_araddr);
        rresp_buf <= `AXI4_RESP_OKAY;
    end else if (rd_state == RD_DELAY) begin
        rd_delay_cnt <= rd_delay_cnt + 4'd1;
    end
end
💡 关键设计：在握手周期同时读取数据
paddr_read(m_araddr) 在 AR 握手成功的同一周期调用，结果锁存到 rdata_buf。之后的延迟周期只是"等待"，不做任何操作。这模拟了真实 SRAM 的行为：地址有效后经过若干周期才输出数据。

AW/W 同时握手

📄 sim_top.sv · 第 291-292 行
// 写通道：AW 和 W 同时握手
wire wr_aw_w_handshake = m_awvalid && m_awready && m_wvalid && m_wready;
⚠️ AXI4 允许 AW 和 W 独立握手
AXI4 规范允许写地址和写数据在不同时刻到达。但 arbiter 在 S_WR_AW 和 S_WR_W 两个状态分别发出 AW 和 W，因此在 Slave 端，AW 总是先于或同时于 W 到达。为简化设计，Slave 要求 AW 和 W 同时握手——这在当前架构下是成立的。

写延迟 + 数据写入

📄 sim_top.sv · 第 317-332 行
always_ff @(posedge clk or negedge rst_n) begin
    if (!rst_n) begin
        wr_delay_cnt    <= '0;
        wr_delay_target <= '0;
        bresp_buf       <= `AXI4_RESP_OKAY;
    end else if (wr_state == WR_IDLE && wr_aw_w_handshake) begin
        wr_delay_target <= 4'(lfsr[1:0] % MAX_DELAY) + 4'd1;
        wr_delay_cnt    <= 4'd1;
        // 写入存储
        paddr_write(m_awaddr, {28'b0, m_wstrb}, m_wdata);
        bresp_buf <= `AXI4_RESP_OKAY;
    end else if (wr_state == WR_DELAY) begin
        wr_delay_cnt <= wr_delay_cnt + 4'd1;
    end
end

paddr_write 在 AW/W 握手成功时立即调用。注意 m_wstrb 直接传递给 DPI-C 的 wmask 参数——arbiter 已经将 core 的 lsu_wmask 映射为 AXI4 的 wstrb。
